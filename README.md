# Katshr — موقع طلبات شحن الألعاب

واجهة عربية/إنجليزية متجاوبة مبنية بـ HTML وCSS وJavaScript Modules، ومناسبة للتحرير من هاتف Android باستخدام Spck Editor. تستخدم Firebase Web SDK من CDN وCloud Firestore لحفظ الطلبات عند تهيئة Firebase.

## محتويات المشروع

- `index.html` — الصفحة الرئيسية ونموذج الطلب المنفصل.
- `styles.css` — التصميم المتجاوب.
- `app.js` — بيانات الألعاب، التحقق من نموذج الطلب، إرسال واتساب، وربط Firestore.
- `firebase-config.js` — إعدادات تطبيق Firebase الخاص بك.
- `firestore.rules` — قواعد Firestore المقيدة للطلبات العامة.

## ما يعمل قبل إعداد Firebase؟

- عرض الألعاب الأربع: Free Fire وPUBG Mobile وMobile Legends وCall of Duty Mobile.
- فتح صفحة تفاصيل الطلب بعد اختيار اللعبة.
- اختيار باقة وإدخال Player ID ومراجعة الملخص.
- إنشاء رسالة واتساب جاهزة إلى رقم الطلب المحدد داخل `app.js`.
- اللغة العربية والإنجليزية والتخطيط المتجاوب.

لا يتم حفظ الطلبات في قاعدة بيانات حتى تهيئ Firebase. عند عدم تهيئته، سيظهر تنبيه ثم يمكن متابعة واتساب دون حفظ قاعدة البيانات. أسعار الباقات غير مفترضة؛ تعرض الواجهة «السعر عند الطلب» إلى أن تضع أسعارك الفعلية.

## المرحلة 1 — إعداد Firebase

1. افتح https://console.firebase.google.com وأنشئ مشروعًا باسم Katshr أو اختر مشروعك.
2. من إعدادات المشروع، أضف تطبيق Web (رمز `</>`).
3. انسخ إعدادات تطبيق الويب التي يعرضها Firebase.
4. افتح `firebase-config.js` في Spck واستبدل القيم الفارغة بالقيم الحقيقية التي يوفرها Firebase. لا تضف علامات اقتباس ناقصة ولا تحذف أسماء الحقول.
5. من Build → Firestore Database أنشئ قاعدة بيانات Cloud Firestore.
6. افتح تبويب Rules والصق محتوى `firestore.rules` ثم انشر القواعد.

## المرحلة 2 — التشغيل من Spck Editor

1. أنشئ مشروع HTML جديدًا في Spck.
2. أنشئ الملفات الخمسة الموجودة في الأرشيف بالأسماء نفسها.
3. الصق محتوى كل ملف في الملف المطابق.
4. شغّل المشروع باستخدام Preview/Live Preview في Spck. يجب فتح الصفحة من عنوان HTTP/HTTPS وليس `file://` لأن JavaScript Modules وFirebase يحتاجان بيئة ويب مناسبة.
5. جرّب اختيار لعبة، ثم اختيار باقة، ثم إدخال Player ID، ثم إرسال الطلب. اختبر واتساب على جهازك.
6. بعد إعداد Firebase، أرسل طلبًا تجريبيًا وافتح Firestore → Data للتأكد من ظهور مستند جديد داخل `orders`.

## المرحلة 3 — تعديل الباقات والأسعار

افتح `app.js` وابحث عن `const GAMES`. كل باقة لها `id` و`nameAr` و`nameEn` و`priceSdg`. أدخل السعر الحقيقي كرقم، مثل `priceSdg: 1500`، أو اتركه `null` ليظهر «السعر عند الطلب». هذه القيمة مثال توضيحي فقط وليست سعرًا مقترحًا أو سعرًا حقيقيًا.

بعد تغيير العروض، اختبر جميع الألعاب واللغتين ورسالة واتساب. لا تضف عرضًا جديدًا قبل تحديث قواعد Firestore إذا كان يتطلب `gameKey` جديدًا.

## المرحلة 4 — النشر المجاني

يمكنك نشر ملفات الواجهة على خدمة استضافة ثابتة تدعم HTTPS، مثل Firebase Hosting. نشر الموقع ليس مفعّلًا تلقائيًا من Spck؛ يتطلب إعداد الاستضافة ونشر الملفات من أداة تدعم أوامر Firebase CLI أو سير عمل Git متوافقًا. راجع الوثائق الرسمية:
- Firebase Web setup: https://firebase.google.com/docs/web/setup
- Firebase Hosting: https://firebase.google.com/docs/hosting

## تنبيهات أمنية مهمة

- إعدادات Firebase الخاصة بتطبيق الويب ليست كلمة مرور إدارية؛ لا تضع مفاتيح Service Account أو بيانات اعتماد إدارية في ملفات الموقع.
- قواعد Firestore تمنع قراءة الطلبات وتعديلها وحذفها من الزوار، وتسمح بإنشاء مستندات طلبات وفق شروط محددة. لكن قواعد Firestore وحدها لا تمنع كل أنواع الإزعاج أو الإرسال الآلي الكثيف.
- قبل إطلاق عام، فعّل Firebase App Check واختبر قواعد Firestore، وفكّر في إرسال الطلبات عبر Cloud Function مع قيود إضافية.
- لا تطلب من العميل كلمة مرور حساب اللعبة أو رمز تحقق. يكفي Player ID وأي تفاصيل لازمة للعبة.
- الكود لا يدّعي نجاح الحفظ: إذا فشل Firebase، يعرض رسالة ولا يفتح واتساب تلقائيًا.
- هذا إصدار أولي قابل للاختبار؛ لا يمكن ضمان انعدام الأخطاء دون اختباره في مشروع Firebase الحقيقي وعلى الأجهزة والمتصفحات المستهدفة.
